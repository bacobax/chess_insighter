## Architecture

The repo is split into a Python backend and a React frontend; they communicate over a local HTTP API.

### Backend (`backend/`)

FastAPI app serving `POST` endpoints under `/api/`. The request/response surface is fully defined in Pydantic models (`backend/models.py`). Services live in `backend/services/` and are called from route handlers in `backend/main.py` via `run_in_threadpool` (all computation is CPU-bound and synchronous).

Key conventions:
- Settings (paths, CORS regex, Stockfish path) are in `backend/settings.py` as a frozen `Settings` dataclass, importable everywhere as `settings`.
- Report data is cached to `.cache/reports/<hash>.json`; the hash is a deterministic digest of request parameters (see `backend/services/cache_service.py`).
- Opening feature rows are loaded once and cached in memory with `@lru_cache(maxsize=1)` in `backend/services/openings_service.py`.

### Analysis Layer (`utils/`)

All heavy computation lives here, independent of FastAPI so it can be used from scripts and notebooks.

| Module | Responsibility |
|---|---|
| `opening_feature_transformer.py` | Extracts calibrated opening features (tactical density, king safety, etc.) from TSV opening lines using Stockfish. Defines `MATCHER_COLUMNS_V2` and `opening_vector_for_color()`. |
| `player_feature_transformer.py` | Builds a `PlayerProfile` and aggregates it into a matcher-ready player vector from enriched games. |
| `player_vector_cache.py` | Loads/stores computed player vectors in `.cache/player_vectors.json`, keyed by a content hash. Entry lookup by username is done in `utils/opening_study_tree.py`. |
| `opening_study_tree.py` | Powers the Opening Study Tree: lazy single-level expansion, style-based scoring (aggressiveness, gambleness, systemness, memory complexity), node serialization. |
| `custom_opening_explorer.py` | Alternative opening lookup tool (separate from the study tree). |
| `game_enrichment_transformer.py` | Per-move enrichment (engine eval, castling, phase classification). |
| `position_feature_extractor.py` | Structural position features (pawn islands, passed pawns, open files, etc.). |
| `global_statistics_transformer.py` | Aggregates enriched games into the full statistics bundle rendered in the report. |

### Opening Data (`openings_dataset/`)

- `all.tsv` — merged TSV from the `chess-openings` submodule; each row is one named opening line.
- `opening_feature_vectors.csv` — **the primary dataset**: 148 rows, one per opening family, with calibrated `white_*`/`black_*`/generalized features, `line_count`, `final_structure_entropy`, `structure_diversity`, `representative_uci`, `representative_pgn`. Regenerated by `build_opening_feature_vectors.py`.
- The player vector stores only the 9 generalized features from `MATCHER_COLUMNS_V2` plus `structure_diversity`. `opening_vector_for_color(row, target_color)` maps the CSV's color-prefixed columns onto those same generalized keys for comparison.

### Frontend (`chess_insighter/`)

React Router 7 SPA (`ssr: false`), Tailwind CSS 4, Radix UI primitives. API base URL defaults to `http://localhost:8000` and is overridden via `VITE_API_BASE_URL`.

Routes (in `app/routes.ts`):
- `/` — username entry form
- `/games/:username` — paginated game list
- `/report/:username` — full player report (fetches statistics + opening matches)
- `/opening-study` — interactive Opening Study Tree whiteboard (`?username=&color=`)

All API calls go through `app/lib/api.ts` → `apiFetch`. Types mirror the backend Pydantic models exactly; they live in `app/lib/types.ts`.

UI primitives (`app/components/ui/`) are hand-rolled (Button, Card, Input, etc.), not from an external component library. Charts use `recharts`. The chess board in the report uses `react-chessboard`; the MiniChessBoard in the study tree is a lightweight CSS/Unicode grid to avoid mounting dozens of heavy board widgets.

### Config (`config/global_statistics_hparams.yaml`)

YAML file controlling all analysis thresholds and weights (centipawn cutoffs, complexity percentiles, result scores, etc.). Loaded once by `backend/services/hparams_service.py`. The config README (`config/README.md`) documents every knob.

## Feature Flags / Important Invariants

- `opening_study_tree.py` is **additive**: it must not affect the existing opening explorer or report pipeline.
- Player vectors in the cache use **generalized** (non-color-prefixed) feature names. Color-specific comparison is done by reading `white_*`/`black_*` columns from the opening CSV, not by storing separate player vectors per color.
- The study-score formula weights are normalized by their sum inside `compute_node_metrics`, so unnormalized weights in API requests still produce valid `[0, 1]` scores.
- `_load_opening_rows` in the study tree is `@lru_cache(maxsize=8)` keyed by file path string — safe for the lifetime of the process but will not see CSV changes without a restart.
